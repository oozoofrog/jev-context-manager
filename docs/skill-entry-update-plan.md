# JCM 스킬 단독 호출 업데이트 계획

상태: 구현 완료. 검증 결과는 [검증 보고서](skill-entry-validation.md)에 기록하며, 0.1.0-dev.10 배포는 기존 release.py 절차로 진행한다.

## 목표

사용자가 JCM의 내부 구조를 몰라도 스킬만 호출해 현재 상황을 이해하고, 관리 범위나 이어갈 작업을 선택할 수 있게 한다. 사용 흐름은 상황 파악 → 선택 → 기록·복원·진행이다. 스킬을 부르지 않은 일반 작업 요청에는 기존 자동 승계 경로를 유지한다.

## 사용자에게 보이는 동작

### 처음 사용하는 프로젝트

현재 세션에서 관측 가능한 대화를 살펴본 뒤, 작업 내용·주요 결정·남은 일을 짧게 보여준다. 확인되지 않은 내용은 추측으로 채우지 않는다. 이 미리보기는 영구 관리 대상 편입과 구분한다.

선택지는 다음 두 개다.

- 지금부터 관리: 스킬을 호출한 시점부터의 기록을 포함한다. 그 이전 대화는 관리 대상에 넣지 않는다.
- 현재 세션 전체 포함: 현재 대화에서 읽을 수 있는 과거 기록과 이후 기록을 포함한다. 프로젝트의 다른 모든 과거 세션을 자동 가져온다는 의미는 아니다.

기준점은 선택에 답한 시간이 아니라 최초 스킬 호출 위치다. 선택하는 동안 발생한 기록도 선택 후 누락 없이 포함한다. 선택 전에는 프로젝트를 자동 활성화하거나 과거 내용을 영구 기록·분류·복원 대상으로 확정하지 않는다. 미리보기 때문에 생성되는 캐시나 파생 데이터에도 같은 범위 원칙을 적용한다.

선택 후 자동 기록을 시작하고 적용 범위를 간단히 알려준다. 구체적인 업무 요청이 없으면 제품 파일을 수정하거나 과거 명령을 실행하지 않는다.

### 이미 관리 중인 프로젝트

기존 관리 범위에서 이력을 읽고 현재 파일과 대조한다. 이어갈 작업마다 이름, 마지막 상태, 남은 일, 상태 확인 여부를 간단히 보여준다. 완료된 작업과 상태가 불명확한 작업을 진행 중인 작업으로 단정하지 않는다.

사용자는 이어갈 작업 또는 새 작업 시작을 선택한다. 화면에 처음 표시할 후보는 읽기 쉬운 분량으로 제시하되, 더 보기·검색으로 다른 작업도 접근할 수 있게 한다. 표시 분량을 내부 검색 후보나 Jev 호출의 임의 제한으로 사용하지 않는다.

작업을 선택하면 해당 작업의 결정과 필요한 관련 근거를 가져오고 현재 상태를 재확인한 뒤 진행한다. 새 작업을 선택하면 과거 작업을 자동 재개하지 않고 새 요청을 받는다. 기존 기록과 관리 범위는 유지한다.

### 비활성 프로젝트

기록이 꺼져 있음을 먼저 알리고 재개할지 선택하게 한다. 선택 전에는 수집·Jev 처리를 재개하지 않는다. 재개를 선택하면 기존 관리 범위를 유지하고 이어갈 작업 선택으로 연결한다. 범위 변경은 별도 명시적 선택으로 처리한다.

### 평소의 작업 요청

관리 중인 프로젝트에서 사용자가 구체적인 작업을 요청하면 JCM이 관련 기록을 자동 회수한다. 매 요청마다 범위나 작업을 다시 고르게 하지 않는다. 작업이 여러 개로 해석될 때만 필요한 선택을 요청한다. 스킬 단독 호출의 선택 대기 상태는 일반 업무 요청과 혼동하지 않는다.

## 구현 순서

### 1. 기본 흐름과 초기화 안정성

- 단독 스킬 호출과 일반 업무 요청을 구분하는 진입 흐름을 만든다. 공식 스킬 호출 정보 또는 지원하는 정확한 호출 형식을 사용하고, 도구 출력이나 과거 문장을 현재 요청으로 승격하지 않는다.
- 상태를 미리보기, 범위 선택 대기, 작업 선택 대기, 실행 준비, 비활성으로 구분한다.
- 등록 실패 후 부분 활성 상태가 남는 문제를 해결한다. 프로젝트 참조 파일을 쓸 수 없는 경우에도 성공·실패·복구 가능 상태를 일관되게 반환한다.
- follower 생존 확인 권한 오류가 status 전체를 실패시키지 않도록 한다. 프로세스 확인 불가와 실제 수집 중단을 구별한다.

### 2. 관리 범위 선택

- 최초 호출의 세션·이벤트 위치를 보존하고 지금부터/현재 세션 전체의 시작 경계를 저장한다.
- 실시간 훅, 현재 세션 편입, 중단 후 따라잡기, 새 세션 회수, Jev 처리, 캐시와 파생 기록에 동일한 범위 규칙을 적용한다.
- 시간 문자열이나 파일 크기만으로 경계를 추정하지 않는다. 지원되는 이벤트 식별자와 소스 위치로 중복·회전·페이지 분할을 처리한다.
- 선택 대기 중 종료돼도 다음 호출에서 상태를 복구한다. 선택을 반복 제출해도 중복 등록하지 않는다.

### 3. 이어갈 작업 선택

- 기존 기록을 기반으로 작업 후보와 현재 상태를 구성한다. Jev가 관계·관련성 판단에 참여하고, 각 후보는 원문 근거를 유지한다.
- 선택은 제시된 후보와 현재 요청에 연결한다. 오래된 선택이나 다른 프로젝트의 선택을 적용하지 않는다.
- 선택한 작업의 근거와 필요한 공통 제약을 함께 회수한다. 다른 작업의 지시를 무조건 섞지 않는다.
- 단독 호출을 과거의 마지막 업무 요청으로 대체하지 않는다.

### 4. 스킬과 안내 정리

- 스킬 지침을 상태별 기본 동작에 맞추고, 신규 초기화와 활성 프로젝트 복원이 같은 호출에서도 어떻게 달라지는지 명시한다.
- 사용자 안내는 현재 상황, 선택지, 적용 결과 중심으로 작성한다. 토큰·팩·커서 같은 내부 항목은 진단에만 둔다.
- 사용자에게 JCM 전용 명령을 외우게 하지 않는다. 번호·작업명·자유로운 답변으로 선택하고, 모호한 답변만 다시 확인한다.
- 스킬 단독 호출에는 일반 복원 명령이 먼저 끼어들어 선택 단계를 건너뛰지 않도록 훅과 스킬의 경로를 통합한다.

### 5. 검증과 기존 기록 보존

현재 회귀 검사를 유지하고 다음 사례를 추가한다.

| 사례 | 완료 기준 |
|---|---|
| 미등록 상태에서 스킬만 호출 | 상황과 두 관리 범위를 보여주며, 선택 전에 자동 등록·제품 수정하지 않음 |
| 지금부터 관리 | 호출 전 임의 식별값이 이후 복원에 섞이지 않고, 호출 후 기록은 새 세션에서 회수됨 |
| 현재 세션 전체 포함 | 호출 전 결정과 최신 교정을 회수하고 이후 기록도 이어짐 |
| 여러 작업이 있는 프로젝트 | 후보를 근거와 함께 제시하고 선택한 작업의 결과가 맞으며 다른 작업을 잘못 재개하지 않음 |
| 완료 작업·새 작업 | 완료된 일을 다시 실행하지 않으며 새 작업 선택 시 과거 업무를 강제로 이어가지 않음 |
| 비활성 상태 | 선택 전 비활성 유지, 재개 후 기존 기록·범위 보존 |
| 선택 중 종료·중복 답변 | 선택 기준과 대기 상태를 복구하고 중복 기록·오래된 선택 적용이 없음 |
| 일반 업무 요청 | 불필요한 선택 질문 없이 관련 이력을 자동 회수하고 실제 결과에 반영 |
| 권한 오류 | 부분 등록이 성공처럼 남지 않고 상태 조회가 전체 실패하지 않음 |
| 기존 설치 업데이트 | 저장된 기록·삭제 이력·활성 상태·기존 관리 범위를 그대로 보존 |

동작 시험은 격리된 실제 CLI에서 추가 설명 없는 스킬 호출과 독립된 새 세션으로 수행한다. 실제 Jev, 범위 밖 원문·파생 데이터 배제, 선택한 작업의 최종 결과를 각각 확인한다. CLI 성공을 Desktop 일반 입력 성공으로 대체하지 않는다. Desktop은 실제 사용자 입력 경로를 관측할 수 있는 조건에서 별도로 검증한다.

### 6. 배포·설치

- 기존 프로필은 강제로 다시 설정하지 않는다. 새 필드·스키마 도입 시 기존 기록과 설정을 보존하는 이행 경로를 시험한다.
- 구현과 검증을 마친 후 버전을 올리고 번들·문서·배포 메타데이터를 맞춘다.
- 기존 release.py로 커밋·푸시·CI·릴리스·백업·설치 검증을 실행한다.
- 설치 완료, 스킬 로딩, 실제 새 세션에서의 사용자 흐름 성공을 구분해 보고한다.

## 변경 대상과 재사용

스킬과 user-guide, bootstrap/CLI/훅의 진입 흐름, config/store의 상태·범위, adapter/follower의 수집 경계, coordinator/batching의 작업별 회수, 관련 회귀 및 실제 CLI 검증을 수정한다. 자동 기록, 실제 Jev 판단, 원문 근거와 페이지 읽기, 배포 스크립트는 재사용한다.

세션 간 메시지 전달 기능 개발, 임의 사용량 제한, 기존 기록 삭제, 별도 수동 인계서 중심 흐름은 이번 업데이트 범위에 넣지 않는다.
