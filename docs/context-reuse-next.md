# 다음 개발 기준: 상황별 문맥 구성과 재사용

상태: 2026-09-28 사용자 평가에 따른 수용 기준. dev.13 후보에 작업 상태·독립 판단 캐시·출처 기반 표현·읽기 계약·관측 지표를 구현했다. 실제 Jev의 고정 corpus 시험 12개와 집중 회귀 25개가 통과했다. 독립 CLI·배포·설치·Desktop 결과는 각 실행의 증거로 별도 기록한다.

## 판단

dev.12는 자동 기록·현재 요청 연결·실제 복원과 선별 정밀도를 개선했다. 235 → 17페이지와 6.87MB → 189KB는 전달량과 선별 개선의 근거다. 동일 시험의 Jev 성공 호출 163회는 재사용과 총 처리 비용이 해결됐다는 근거가 아니다.

[Diogo 원문](https://docs.google.com/document/d/1G61uUB0FifUnmmrPzFQojZ3KpczYKmXGpgEXDJ2l_Zg/edit)을 다시 확인했다. 질문별 동적 문맥과 표현 수준, 기존 문맥의 효용과 재구성 비용, 관련 정보 탐색 결과의 공유라는 방향을 따른다. 전수 판단은 원문에도 있는 초기 접근이다. 전수 판단 자체를 금지하거나 임의 호출 상한을 넣는 것이 목표가 아니다.

초기 설계의 §2, §7, §9.4–9.5, §10.2–10.3, §11.1을 완료 기준으로 유지한다. 저장된 원문/이벤트가 정본이고 task view, assertion, 색인, 표현과 pack은 재생성 가능한 파생 자료다. Codex 내부 KV 캐시, 모델 라우팅, 하위 에이전트 orchestration은 이번 범위가 아니다.

## 우선 구현할 작은 종단간 경로

같은 작업을 세션 A에서 복원 → 세션 B에서 표현을 바꿔 다시 요청 → 새로운 교정 한 건 유입 → 세션 C에서 수정된 작업 문맥을 복원한다.

- 두 번째 요청은 이미 준비한 작업 상태와 근거 표현을 재사용한다. 문구가 비슷하다는 이유만으로 같은 작업이나 같은 질문이라고 확정하지 않는다. 사용자 선택/확인된 task identity를 우선하고, 달라진 의미는 좁은 Jev 판단으로 확인한다.
- 새 교정은 현재 상태와 의존 자료를 무효화하고 필요한 부분만 다시 판단한다. 다른 작업의 결과까지 모두 폐기하지 않는다.
- 새 세션에는 현재 목표·적용 제약·결정·미해결 항목·충돌과 필요한 근거를 먼저 전달한다. 원문 확장과 감사 상세는 별도 읽기 경로로 제공한다.
- 자동 수집과 새 세션 복원은 유지한다. 사용자의 checkpoint 작성이나 매번 sync 실행을 전제하지 않는다.

## 구현 순서와 계약

| 순서 | 산출물과 코드 소유 경계 | 검증할 불변식 |
| --- | --- | --- |
| 1. 작업 상태와 변경분 | `store` 파생 테이블과 `worker` 증분 투영. task/source revision, assertion span, basis, scope, unresolved 관계, read revision을 유지한다. | source·정책·모델·rubric·관련 근거 변경에 따른 정확한 무효화. 오류/중단 재시도에서 누락·중복 없음. 과거 assistant 완료 보고를 현재 검증으로 승격하지 않음. |
| 2. 재사용과 후보 검색 | `coordinator`의 task view·projection·경로/심볼·Unicode/ngram 색인·관계 이웃의 합집합. `provider`의 재사용 키를 독립적인 판단 단위로 분리한다. | 묶음 경계가 바뀌었다는 이유로 동일한 독립 판단을 재호출하지 않음. 이웃에 의존하는 판단의 조건을 키에서 생략하지 않음. 미분류 tail과 교정/충돌 후보를 보호하고 빈틈 시 검색을 확장함. |
| 3. 표현과 읽기 계약 | 출처 span/hash·생성자·버전·상세 수준을 가진 짧은 표현/상세 표현/원문. `delivery`와 스킬에서 필수 문맥과 선택 확장을 구분한다. | 필수 제약의 부정·예외·조건을 보존함. 요약은 정본이 아니며 원문으로 확장 가능. 필수 자료의 실제 읽기는 확인하되 모든 감사 정보를 의무 소비로 계산하지 않음. |
| 4. 비용과 효용 관측 | 차가운 요청, 반복 요청, 교정 후 요청을 비교하는 live acceptance와 공개된 집계 결과. | 복원 정확도와 비용 지표를 함께 통과해야 개선으로 판정함. 기록 수/호출 수의 임의 상한으로 지표를 낮추지 않음. |

Jev는 제시된 근거의 분류·관계 후보·적용 범위·표현 선택을 판단한다. 제시되지 않은 내용을 생성하거나 완료·권한을 확정하지 않는다. 자연어 요약은 기존 Astra 작업 경계에서 출처와 함께 생성하고, 준비되지 않았으면 근거가 확인된 발췌/원문을 사용한다. 요약 생성을 새 사용자 의무나 숨은 추가 모델 호출로 만들지 않는다.

`supersedes/resolved`는 단순한 최신 순서 또는 Jev의 후보 관계만으로 확정하지 않는다. 명시적 교정의 적용 범위와 근거가 확인될 때 갱신하고, 불확실하면 양쪽과 충돌을 유지한다. 삭제·비활성·egress 정책은 캐시 및 파생 상태 재사용보다 우선한다.

## 수용 시험

1. **변경 없는 반복:** 동일 task/revision의 문구가 다른 요청에서 같은 필수 제약과 미해결 사항이 복원된다. 기존 원문 전체를 다시 보내지 않고 task 판별에 필요한 좁은 판단과 새 요청만 처리하는지 기록한다.
2. **한 건의 교정:** 새 교정과 의존하는 assertion/표현/관계만 갱신한다. 해당 범위 밖의 분류를 재호출하지 않는지 decision provenance로 확인한다. 정정 전 값이 현재 요구로 남으면 실패다.
3. **공통 제약과 충돌:** 다른 작업에서 정한 적용 가능한 공통 제약을 가져오고, 무관한 작업은 제외한다. 확인되지 않은 상충 요구는 양쪽을 제공한다.
4. **누락과 확대:** 로컬 색인에 없는 동의어/한국어 표현, 미분류 최신 요구, 부정 조건, 큰 도구 결과 속 예외를 포함한 fixture로 recall을 검증한다. 필요한 경우 검색·원문 읽기를 확장하고 불완전성을 숨기지 않는다.
5. **표현 단계:** 간단한 재개에는 필수 task frame과 근거 표현을 읽고, 세부 질문에서 원문을 확장한다. 선택 감사 정보를 읽지 않아도 필수 소비가 완료될 수 있어야 한다. 필요한 근거를 읽지 않았으면 복원에 사용했다고 주장하지 않는다.
6. **무효화와 삭제:** source revision, 정책/egress, tombstone, rubric/model, 관련 파일 snapshot이 바뀌었을 때 낡은 문맥/검증을 재사용하지 않는다. 서로 다른 task의 동시 읽기는 일관된 read revision을 따른다.
7. **실사용:** 실제 Jev, 독립 새 CLI 세션, 기존 Desktop의 호스트 전달 요청을 각각 실행하고 실제 결과 반영을 확인한다. 설치·캐시 적중·전달·읽기·사용을 별개 결과로 보고한다.

## 측정

| 항목 | 보고할 값 |
| --- | --- |
| 복원 품질 | 필수 요구/교정/예외 recall, 확인된 충돌 보존, 오래된 검증 오인, 작업 간 잘못된 혼입 |
| Jev 처리 | 실제 HTTP 호출, 캐시 적중, 재평가한 source/span 수, 전송 bytes와 제공자 usage tokens, 실패/재시도 |
| Astra 전달 | 필수/선택 제공 bytes와 실제 served bytes, 읽은 표현 단계, 불필요한 원문 확장. 토큰 추정과 호스트가 실제 관측한 usage를 혼동하지 않음 |
| 시간 | 수집, 상태 갱신, task 판별, 후보 선별, pack 준비, 필수 읽기 완료의 구간별 경과 시간 |
| 재사용 | 재사용된 assertion/판단/표현의 근거 revision, 무효화 원인, 변경분 처리량 |

먼저 동일 corpus와 필수 정답 집합으로 기준선을 고정한다. 반복 요청의 원문 재전송과 불필요한 재평가가 줄고, 필수 근거 품질이 유지돼야 통과다. 단일 사례의 비율을 일반 성능 보장이나 KV 캐시 개선으로 표현하지 않는다.
