# JCM 1.0.0

First stable release of Jev Context Manager for local Codex session continuity.

JCM captures supported public conversation records and restores source-backed
working context across sessions. Recovery now selects evidence and detail for the
current question independently of reusable task identity. Resuming implementation,
explaining an exception and diagnosing a failure can share task state while
receiving different source excerpts.

- Reuse source classification, task membership, assertions and correction judgments.
- Reuse equivalent questions without confusing a changed focus with the same
  information need. Relative questions are reconsidered when their source context changes.
- Preserve user constraints, exceptions, corrections, unresolved issues and source
  expansion paths. Historical claims never establish current implementation or verification.
- Keep unchanged properties intact when another clause is corrected.
- Accept transcript records by structure and session/project identity rather than
  a Codex version allowlist; unsupported structures remain explicit coverage gaps.

Validation includes the full regression and packaging suite, real Jev fixtures
with 13 question-selection checks and 12 existing context-reuse checks, and
source-to-bundle consistency. The release pipeline additionally requires Linux CI
and installation from the exact published commit in an isolated environment.
See [current-question validation](../query-context.md) for detailed evidence and limits.

The journal upgrades to schema 6 on first use by this runtime. Existing records
are preserved; older runtimes reject schema 6. Back up the store before upgrading
if a rollback to a previous runtime is needed.

Requires Python 3.11+ and `TYPESAFE_API_KEY` for Jev judgments. Provider failures
retain available evidence and mark recovery degraded. Selection fixtures do not
establish Desktop consumption or correctness of a downstream generated answer.
