# JCM 1.0.2

Query-specific recovery preserves the current decisions, constraints, corrections,
blockers and source evidence while reducing repeated consumer input. Required
evidence is selected once and retained through brief, core and native delivery;
compact references do not replace facts needed to act. Within a task, exact
retained-context deltas carry changed records and remove obsolete fields. Verified
task transitions replace the active full view while preserving work history.

The accepted comparison is starting JCM brief/delta versus improved JCM brief/delta
on seven prepared flows: cold consumer recovery, unchanged-source warm reuse,
changed question, partial correction, dependent scope, independent task B and
return to corrected A. Both execution orders passed all 28 exact answers and
primary source/read/exposure/policy/usage gates.

| Execution order | Baseline input | Improved input | Reduction |
|---|---:|---:|---:|
| Baseline then improved | 646,020 | 569,124 | 11.9030% |
| Fresh improved then baseline | 680,008 | 570,190 | 16.1495% |
| Combined | 1,326,028 | 1,139,314 | 14.0807% |

Uncached input increased from 420,684 to 425,714 (+1.1957%), so reduced total
input does not establish a lower monetary bill. Additional reads fell from 7
to 2 and aggregate execution time from 346.511s to 309.586s; some individual
stages became slower. The first pair retains its 13 completed stages and adds
only the formerly unpaid last stage in the same session. Its 5,141.652s interruption
is separate from execution time.

Optional provider calls/input/output during both consumer comparisons were zero.
Historical preparation still used 238 Jev calls, input 1,627,855/output 89,587,
including 99 earlier baseline calls. Archive reuse does not erase that cost.
The selected consumer comparisons used input 2,465,342/output 7,280 over 28 turns
and 65 response receipts. Earlier failed-run known costs and interrupted unknowns
remain historical records outside this selected comparison.

This evidence does not establish preparation/indexing savings, JCM-versus-no-JCM
savings, full 7,230-event historical recovery, installed Desktop capture/hooks,
monetary savings or universal performance. Original failures, malformed checksum
metadata and the initial SQLite preflight header change remain preserved privately;
acceptance uses independently checked current bindings. Supporting repairs keep
reader/runtime/prompt and primary gates unchanged.

The package, plugin and bundled runtime are synchronized at 1.0.2. Runtime changes
from the accepted candidate are limited to the version field. The release pipeline
requires the full offline regression suite, source-matching wheel/bundle, exact
main/tag commit, CI, published exact-ref lifecycle fixture, and backed-up local
plugin installation. Fresh app-server skill discovery and current Desktop UI
visibility are reported separately; plugin installation does not activate projects.

See the [public consumer evidence](../../evidence/continuity-consumer-1.0.2.json)
and [release/install procedure](../releasing.md). Detailed original transcripts,
experimental raw logs and private storage are not part of the release.
